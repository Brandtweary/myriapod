
It is not until the hammer breaks that you perceive it as a separate object to yourself. This is *zuhandenheit*, as coined by Martin Heidegger, roughly translated as "readiness to hand". The less aware you are of a tool, the more effective it is at its job. The concept applies beautifully to artificial intelligence and computers more broadly, which feel magical when they work and excruciating when they don't. 

Based on this principle, it may seem at first like the trend towards more autonomous AI is the right direction; after all, what could be more frictionless than an AI agent churning away on some distant server that you never look at? But when that agent inevitably makes a mistake, who feels the breakage and suffers for it? The AI won't, but you will, and slower than if you had a proper interface for monitoring the agent's work. We're basically inventing hammers that break in increasingly silent and mysterious ways.

To reverse this trend, we need AI interfaces that are a pleasure to use and create tight coupling between the user and agent. In the current era, this means fast, transparent, hackable, and voice-first. Not autonomous AI, but *cybernetic* AI, in the original sense of the word, meaning driven by feedback loops. The human and agent create a single coupled system, and the dance between the two is what creates value. The irony is that people associate cybernetics with machine implants, but we won't ever need them because voice-enabled AI is already the perfect interface for computers. Voice IS the universal interface, it's how humans already talk to each other. AI doesn't replace employees, it replaces the keyboard and mouse. 

**Myriapod** is an open-source voice assistant, powered by open-weights models, with a lexicon-based memory. We experimented with other memory systems, including ColBERT-RAG and knowledge graphs, but found that none added any value beyond a basic term-matching glossary. In the vast majority of cases, you don't actually need your assistant to fuzzy-match your queries to stored memories, you just need it to understand the precise definitions of terminology that you use. Fuzzy memory systems waste tokens with junk results, create maintenance burden, and give the false impression of long-term memory that the agent doesn't actually have. Myriapod does have a running context system which ensures continuity between sessions over a 1-2 week period, but we're not claiming to offer true human-level long-term memory (which is an open problem anyway). 

Myriapod has automated memory ingestion and maintenance workflows, and we call these systems **autonomic** to distinguish them from autonomous AI. They're autonomic in the same sense as your heartbeat or digestion. They fire in the background without prompting and conduct routine tasks essential for harness health. Myriapod is NOT an agent swarm — that would be adding another layer of abstraction between the user and AI. It is a single agent with an autonomic nervous system. 

Myriapod is open-source and uses exclusively open-weights models, but it is not recommended to run locally on consumer hardware at time of writing (2026). GLM-5.2 requires a stack of H100 GPUs, which is why we serve it over OpenRouter (Zero Data Retention endpoints only). It's still more private and sovereign than most cloud-based AI providers. No one can censor your chats, and if one OpenRouter provider goes down your chat is routed to a different one instantly. We currently do not support model selection in the web app. If you would like to choose different models or set up your own local server, you will need to clone the [Myriapod repo](https://github.com/Brandtweary/myriapod) and follow the instructions there to run a self-hosted instance.

Myriapod v1 is suitable for casual chat and research, but it does not currently have the tooling necessary for coding or drafting documents. If you're interested in these features, you can sign up to our email list below and we'll alert you for new releases.
